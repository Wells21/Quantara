## 1. Executive determination

Having read both books end to end, the determination is unchanged in substance from the prior assessment, but is now grounded in exact formulas and algorithms rather than paraphrase:

Quantara is **not starting from the wrong foundation**. Its architecture already implements a real subset of AFML faithfully: event-driven bars, dynamic triple-barrier geometry, side-specialized meta-labeling, concurrency-aware sample weights, fractional differentiation, an exact Bid/Ask execution replay engine, and — as of the two most recent work sessions — a genuine four-layer outcome ontology, an exact-interval purge primitive, a canonical AFML Chapter 10 sizing reference implementation, and an audit-only executable-target engine that has already surfaced a real, measured discrepancy between gross and executable outcomes on a live pilot edge (see §3).

Quantara is **not yet MLDP-faithful end to end**. The most serious open issues are conceptual, not cosmetic, and several of them can now be traced to a *specific, named* algorithm in the books rather than a general principle:

1. Historically, Quantara trained its meta-model on the gross research label (`meta_label = 1[realized_r > 0]`) and then fit a sigmoid mapping that same model's probability onto a *different* target, `executed_meta_label = 1[executed_r > 0]`. AFML never licenses this: probability calibration is defined as recovering a well-calibrated estimate of the probability of the event the model was trained to predict (AFML Ch.9 §9.4's log-loss discussion, AFML Ch.10 §10.3's bet-sizing derivation) — it is not a mechanism for retargeting a model after the fact. This is a target-identity violation, not calibration. **Task 1/Task 2A have begun correcting this** (see §3) but the correction is not yet complete end-to-end.
2. Quantara's live "payoff-aware AFML" bet sizing is a **Quantara extension**, not AFML Chapter 10's canonical rule. AFML Ch.10 §10.3 (book p.142–144) specifies the bet size from a predicted probability as an exact, closed-form transform of a z-statistic against a null of `p=1/2` (binary) or `p=1/num_classes` (one-vs-rest) — `m = 2·Z[z] − 1` or `m = x·(2·Z[z]−1)` — with **no empirical break-even rescaling** anywhere in the derivation. Quantara's empirical break-even rescaling must be retained only as a named, independently-benchmarked extension (`quantara_extension_bet_size`), compared against the canonical reference (`afml_ch10_bet_size_reference`) out of sample.
3. Quantara did not, until Task 1, have a global immutable trial ledger. AFML Ch.11 (book p.153–159) and MLAM Ch.8 (book p.105–124) both treat this as existential: MLAM's own worked numerical example shows that out of 1,000 backtested strategies with a true positive rate of only 1/100, standard significance thresholds (α=0.05, β=0.2) yield a false-discovery rate of **≈86%** among "significant" results (MLAM p.113) — and AFML Ch.11 explicitly attributes an *increasing*, not decreasing, false-discovery risk to a *more* experienced backtester, because experience means more prior undisclosed trials on the same dataset (AFML p.152–153).
4. Quantara's horizon/grid discovery process is exactly the "backtest-tweak-backtest" loop MLAM warns against by name (MLAM §1.4.2, p.8–9: "backtesting while researching is like drinking and driving," restated in AFML Ch.11 as "Marcos' Second Law of Backtesting," AFML p.153). The existing V3 horizon scans are not void — they remain useful discovery evidence — but they cannot be treated as untouched out-of-sample evidence, because their outcomes have already informed choices already made (AFML p.155–158's CSCV/PBO framework; MLAM §8.1–8.2 gives the same argument in general precision/recall terms).
5. Quantara's feature-clustering and portfolio-clustering layers use raw empirical correlation matrices without the Marcenko-Pastur-based denoising MLAM Ch.2 specifies (MLAM p.24–37), and without the Optimal Number of Clusters (ONC) algorithm MLAM Ch.4 specifies (MLAM p.52–64) in place of a fixed Ward-linkage distance threshold. MLAM's own Monte Carlo shows denoising alone cuts minimum-variance-portfolio weight RMSE by **59.85%** and maximum-Sharpe weight RMSE by **94.44%**, versus 30.22%/70.77% for Ledoit-Wolf shrinkage alone, with shrinkage adding essentially nothing once denoising is applied (MLAM p.32–36, Figures 2.5–2.6). This is not a marginal refinement; it is the single highest-leverage, cheapest-to-implement fix in the entire migration.
6. Quantara's shared CPCV/purge helper does not implement AFML's actual purge algorithm. This blueprint can now say exactly *why*: AFML's fully general purge routine (`getTrainTimes`, Snippet 7.1, AFML p.105–106) checks three explicit interval-overlap conditions of every training label against *every* testing label. The `PurgedKFold.split()` class (Snippet 7.3, AFML p.108–109) that most implementations (including, evidently, Quantara's) actually call is a **simplified special case** valid only for contiguous, non-shuffled KFold blocks — it uses a `searchsorted` shortcut for the left training block and only explicitly embargoes the right block. If Quantara's shared helper mirrors Snippet 7.3's shortcut rather than Snippet 7.1's general three-condition test, that is precisely the source of the previously-flagged "not an exact interval-overlap implementation" finding. This is now a confirmed, mechanical bug locus, not a suspicion.

The recommended approach is unchanged from v1.0: **a controlled foundation migration, not another patch around `executed_r`.** What has changed is that this document can now specify, for almost every item above, the *exact* algorithm Quantara's code must be checked against, with a page citation, because both books have now been read directly rather than summarized secondhand.

## 2. What "follow López de Prado exactly" means

The two books are a methodology and a research factory, not one fixed trading algorithm — this was true in v1.0 and remains true. Concretely, having now read every chapter:

- **AFML's own stated meta-strategy paradigm** (AFML Ch.1 §1.2.2, p.4–5) is itself the organizing principle Quantara should hold itself to: a research assembly line of data curators → feature analysts → strategists → backtesters → deployment team → portfolio oversight, each a distinct discipline with distinct failure modes. Quantara's `shared/` library plus per-edge `research/` station scripts (01–09) is already structurally this factory. That should be preserved and reinforced, not replaced.
- **Use the book's exact mathematical object when Quantara claims to implement that object.** Where this blueprint gives a formula below, it is transcribed to the symbol, not paraphrased — because the previous, secondhand blueprint could not make this promise and Quantara's own code should be checked against these formulas directly, not against a description of them.
- **Preserve the book's chronology, information sets, sample-overlap logic, and anti-leakage constraints** — this is the single idea AFML Ch.4/Ch.7 and MLAM Ch.8 return to most often, under different names (concurrency, purging, embargo, familywise error rate).
- **Do not call a Quantara modification "AFML" when it is an extension.** MLAM is explicit that ML's most scientifically valuable use is discovering a testable theory, not merely producing a good-looking backtest (MLAM §1.2, p.2–4) — a mislabeled extension undermines exactly this by hiding which parts of the pipeline are genuinely theory-grounded canon versus which parts are untested production convenience.
- **Where MLAM (2020) refines or extends an overlapping AFML (2018) method, treat MLAM as the later methodological reference** unless there is a documented reason not to. Concretely: MLAM's Clustered Feature Importance (MLAM §6.5.2, p.85–87) supersedes AFML Ch.8's plain MDI/MDA for correlated-feature settings; MLAM's Nested Clustered Optimization (MLAM §7.6, p.96–102) is offered as a benchmark against, not necessarily a replacement for, AFML Ch.16's Hierarchical Risk Parity; MLAM's trend-scanning label (MLAM §5.4, p.68–70) is a genuinely new labeling method not present in AFML at all.
- **Allow production realism beyond the books** (Bid/Ask, broker minimum lots, prop-firm constraints, latency, MT5 execution) but **separate those extensions from the canonical reference layer and test them independently.** Both books are explicit that they do not model these things and do not need to — AFML's own bar-construction chapter (Ch.2) is about sampling and information content, not broker mechanics; nothing in either book is violated by Quantara's execution-realism layer, provided it is not mislabeled as a canonical AFML/MLAM object.
- **Treat theory, not backtest profitability, as the reason an edge exists.** This is MLAM's single most repeated thesis, stated in its very first substantive section: "a historical simulation of an investment strategy's performance (backtest) is not a theory; it is a (likely unrealistic) simulation of a past that never happened" (MLAM p.2).
- **Treat every research choice that looked at outcomes as a trial that contributes to selection risk.** This is the operational meaning of AFML Ch.11's CSCV/PBO framework (AFML p.155–158) and MLAM Ch.8's False Strategy theorem (MLAM p.105–124, Appendix B proof p.128–129), both of which this blueprint now specifies to exact formula.

## 4. Canonical method reference and discrepancy register

This section replaces v1.0's discrepancy table with one grounded in exact formulas from the books, organized by AFML/MLAM chapter. Each row states: what the book prescribes (with the exact object, not a paraphrase), what Quantara currently does, and the determination.

### 4.1 Data structures and sampling (AFML Ch.2, book p.23–41)

- **Bars.** AFML's stated preference ordering is dollar bars ≻ volume bars ≻ tick bars ≻ time bars, and it explicitly recommends *against* time bars because information does not arrive at a constant clock rate (AFML p.25–26). Quantara's `standard_quote_tick` bar is **not** one of AFML's four standard bar types nor one of its information-driven bars (tick/volume/dollar imbalance bars, tick/volume/dollar runs bars, AFML p.29–32) — all of the latter are defined strictly on signed transaction ticks `(p_t, v_t)` via the tick rule `b_t = sign(Δp_t)` applied to **actual trade prints**, not quote updates. **Determination: `standard_quote_tick` is a `DATA_CONSTRAINED_ADAPTATION`, not a literal AFML bar.** It should be renamed/documented as a quote-activity bar at the interface level, with compatibility aliases preserved only where needed, and a documented rationale for why it is used in place of a true information-driven bar (namely: if Quantara's underlying feed for a given instrument is Bid/Ask quotes without confirmed trade prints and volume, none of AFML's tick/volume/dollar/imbalance/runs bars can be constructed as specified — a quote-midpoint-change proxy is not what the book prescribes and must be labeled as such if used).
- **CUSUM event filter** (AFML p.38–40). Exact symmetric two-sided recursion: `S+_t = max(0, S+_{t-1} + y_t − E_{t-1}[y_t])`, `S-_t = min(0, S-_{t-1} + y_t − E_{t-1}[y_t])`, event triggers and **both** accumulators reset to 0 the instant either `S+_t > h` or `S-_t < −h`. If Quantara's candidate-event engines use anything resembling a static-threshold indicator that re-triggers on every bar a value hovers near a boundary (e.g., a naive Bollinger-Band-style trigger) rather than this reset-on-trigger recursion, that is a deviation from the book's stated advantage of CUSUM over such indicators (AFML p.40). Should be checked directly against `shared/edges`'s candidate-event engines.
- **ETF trick / ETF-trick-style AUM recursion** (AFML p.33–34) is the canonical way to handle multi-instrument/rolling-future series as one continuous series; **Quantara does not need this** for single-instrument quote-tick edges unless/until a spread or basket edge is introduced, at which point it becomes directly applicable (holdings recursion `h_{i,t}`, AUM recursion `K_t = K_{t-1} + Σ h_{i,t-1}φ_{i,t}(δ_{i,t}+d_{i,t})`).

### 4.2 Labeling (AFML Ch.3, book p.43–57; MLAM Ch.5, book p.65–73)

- **Triple-barrier method** (AFML p.45–47): this is confirmed as Quantara's actual labeling mechanism and is structurally faithful. Two specific implementation-level checks the book leaves as explicit reader choices rather than fixed defaults, and Quantara must document its own choice for each rather than silently inheriting one: (a) when the *vertical* barrier is touched first, whether the label is `sign(return)` (the author's stated personal preference, AFML p.46) or forced to `0` — the book's own reference `getBins` snippet does **not** implement the zero-forcing case, leaving it as an unimplemented exercise (AFML p.47); (b) barrier configuration choice among the three "useful" configurations `[1,1,1]`, `[0,1,1]`, `[1,1,0]` versus the three "less realistic" and two "illogical" configurations the book itself enumerates and rules out (AFML p.46).
- **Meta-labeling** (AFML p.50–53; MLAM §5.5, p.71–73): confirmed structurally faithful — side-specialized edges fix direction and the meta-model decides size, which is exactly AFML's stated purpose ("meta-labeling's job is explicitly NOT to invent new betting opportunities," AFML p.51). MLAM adds two closed-form bet-sizing formulas beyond AFML Ch.10's single-model case that Quantara does not yet have as named reference implementations: **bet sizing by expected Sharpe ratio** for a single meta-labeling classifier (`z=(p−1/2)/√(p(1−p))`, `m=2Z[z]−1`, MLAM p.70 — algebraically identical to AFML Ch.10's binary case) and **ensemble bet sizing** for `n` independent meta-labeling classifiers using a Student-t statistic (`t=(p̂−1/2)/√(p̂(1−p̂))·√n`, `m=2·t_{n-1}[t]−1`, MLAM p.71) — the latter is new relevant reference material if Quantara ever ensembles multiple meta-models per edge.
- **Trend-scanning** (MLAM §5.4, p.68–70): a genuinely new labeling method not present in AFML at all. Fits a linear time-trend over a *set* of candidate look-forward horizons `L`, picks the `L` maximizing `|t-value of the slope|`, and labels by the sign (classification) or magnitude (regression/sample-weight) of that t-value. **This is not currently part of Quantara's edge lifecycle and is a legitimate MLAM-sourced candidate labeling method** worth benchmarking for edges where a fixed vertical horizon feels arbitrary (e.g., trend-family edges), since it removes the need to pre-specify a single holding horizon entirely.
- **`realized_r`/`executed_r` ontology** (P0.1 in §5 below): the four-layer separation Task 1 installed (`gross_r`, `quote_executable_r`, `net_executable_r`, `live_realized_r`) is not itself an AFML/MLAM object — it is a **Quantara extension** built to implement AFML/MLAM's underlying labeling/meta-labeling semantics correctly under Quantara's own execution-realism requirements. It should remain registered as `QUANTARA_EXTENSION` in the method registry (as it already is), not relabeled as canonical AFML.

### 4.3 Sample weights (AFML Ch.4, book p.59–73)

- **Concurrency, average uniqueness, return attribution** (AFML p.59–70): confirmed structurally implemented and should be preserved. Exact formulas for fixture-level regression tests: concurrency `c_t = Σ_i 1_{t,i}`; average uniqueness `ū_i = (Σ_t u_{t,i})/(Σ_t 1_{t,i})`, i.e. the reciprocal of the harmonic mean of concurrency over the label's lifespan; return-attribution weight `w̃_i = |Σ_{t=t_i,0}^{t_i,1} r_{t-1,t}/c_t|`, rescaled so `Σw_i = I`.
- **Sequential bootstrap** (AFML §4.5.1–4.5.2, p.63–65): Quantara does **not** currently have a first-class sequential-bootstrap training path (per the prior deviation register, item D-class "conditional gap"). This is correctly scoped as **P2 unless bagging/bagged estimators are adopted** — AFML itself is explicit that sequential bootstrap's entire purpose is correcting overlap-driven redundancy specifically for *bagged* estimators (AFML p.62: "bagging is only effective to the extent that ρ̄ < 1," AFML p.94–95's exact variance formula `V[(1/N)Σφ_i] = σ̄²(ρ̄+(1−ρ̄)/N)`) — if Quantara's meta-models are XGBoost (boosted trees, not bagged), sequential bootstrap is not load-bearing for them today, and forcing it in "merely to tick a checklist" is explicitly the wrong instinct per this same reasoning. It becomes directly relevant only if/when Quantara adopts a bagging-family model or a Random-Forest-style estimator.
- **Time decay, class weights** (AFML p.70–72): optional refinements, correctly scoped as non-mandatory.

### 4.4 Fractional differentiation (AFML Ch.5, book p.75–89)

- Confirmed structurally implemented (train-segment fixed-width FFD). Exact recommended procedure per AFML p.88: (1) cumulative-sum the raw series; (2) compute FFD(d) for a candidate grid `d∈[0,1]`; (3) find the **minimum** `d` such that the ADF-test p-value on FFD(d) falls below 5%; (4) use that series. AFML's own empirical validation across 87 liquid futures contracts found stationarity achieved with `d<0.6` in every case, and in some instruments no differentiation at all was needed (AFML p.86–87) — the explicit conclusion drawn is that most finance literature over-differentiates by defaulting to `d=1` (plain returns), destroying most of the series' memory unnecessarily. **The prior deviation register's "not fully auditable against AFML criterion" (P1) finding should be resolved by persisting, per feature per training window: the candidate `d` grid, the ADF statistic/p-value at each `d`, the correlation between the raw and FFD(d) series (a directly interpretable memory-preservation diagnostic — AFML's own worked example shows FFD(d=0.35) preserves 0.995 correlation with the original series versus only 0.03 for plain returns, AFML p.85), the selected minimum `d`, and proof `d` is frozen (not re-estimated) at live-runtime.**

### 4.5 Cross-validation, purging, embargo (AFML Ch.7, book p.103–111) — **P0, confirmed root cause**

This is the single most concrete, mechanically-specific finding in this blueprint, because the book gives two different algorithms under the same conceptual heading and Quantara's deviation was previously described only qualitatively.

- **The fully general purge algorithm is `getTrainTimes` (Snippet 7.1, AFML p.105–106).** For every testing-set label with information interval `[t_j,0, t_j,1]`, drop from the training set every label `i` satisfying **any** of three conditions:
  1. `t_j,0 ≤ t_i,0 ≤ t_j,1` (training observation starts inside the test interval),
  2. `t_j,0 ≤ t_i,1 ≤ t_j,1` (training observation ends inside the test interval),
  3. `t_i,0 ≤ t_j,0 ≤ t_j,1 ≤ t_i,1` (training observation envelops the entire test interval).
  This must be checked against **every** individual testing-set label's interval, not merely against the earliest-start/latest-end bounds of the test set taken as a whole — unless the test set is genuinely contiguous with no training observations interleaved within its span, in which case (and only then) the check may be collapsed to one combined interval.
- **`PurgedKFold.split()` (Snippet 7.3, AFML p.108–109) is a *simplified, optimized special case*** of the above, valid **only** when train/test splits come from contiguous, non-shuffled KFold blocks. It uses a `searchsorted` shortcut to build the left training block (all labels ending at or before the test fold's start) and applies an explicit embargo gap only to the right training block. It does **not** re-run the general three-condition check against arbitrary interior training labels — it assumes contiguity structurally.
- **Embargo mechanism** (AFML p.107–108): applied by extending the *test* interval's right edge to `t_j,1 + h` **before** running the purge check — i.e., embargo is not a separate post-hoc step, it widens the interval purging tests against, on the post-test side only (no embargo is needed on the pre-test side, since a training label ending strictly before the test interval begins cannot leak forward information). Recommended magnitude: `h ≈ 0.01·T` (about 1% of the bar count) as a starting point, confirmed empirically by checking that CV performance stops improving as the number of folds `k→T` (AFML p.106–107) — if it keeps improving indefinitely, that is itself the diagnostic that leakage remains.
- **Determination:** if Quantara's shared CPCV/purge helper is built on (or resembles) the `PurgedKFold.split()` shortcut rather than `getTrainTimes`'s general three-condition test, this is very likely the exact mechanical cause of the previously-flagged "not an exact interval-overlap implementation" finding, and it is now fixable by a direct, line-level comparison against Snippet 7.1 rather than a redesign from first principles. **This is the single highest-priority code-level fix in this blueprint** (see P0.3 in §5).
- Embargo itself must stop being an unexplained hard-coded constant (previously flagged, still open): it needs a documented unit, rationale, relation to feature lookback/serial dependence, and a leakage-sensitivity audit proving that increasing folds does not monotonically improve performance.

### 4.6 Ensemble methods (AFML Ch.6, book p.93–102)

- AFML's own stated preference for finance is **bagging over boosting** (AFML §6.6, p.100–101), reasoned explicitly as: bagging addresses overfitting (finance's dominant risk given low signal-to-noise ratio) while boosting addresses underfitting, at greater overfitting risk, and boosting cannot be as easily parallelized. **Quantara's XGBoost-primary-model choice is therefore explicitly a deviation from AFML's stated preference, not merely "allowed."** This does not mean XGBoost must be abandoned — the book does not forbid boosting — but per the prior deviation register this "requires stronger overfit controls" (P1), and this blueprint specifies exactly what those controls are: purged/embargoed CV done correctly (§4.5), the full CPCV path-distribution evaluation (§4.7), and the PSR/DSR/PBO firewall (§4.8) — i.e., boosting is permissible provided the overfitting-control machinery around it is complete, which per §3.3 it currently is not.

### 4.7 Backtesting, CPCV, and synthetic data (AFML Ch.11–13, book p.151–193; MLAM Ch.8, book p.105–124) — **P0**

- **Exact CPCV path-count formula** (AFML §12.4.1, p.164): for `T` observations split into `N` contiguous groups and testing sets of `k` groups, the number of distinct backtest paths is
  `φ[N,k] = (k/N)·C(N,N−k) = ∏_{i=1}^{k−1}(N−i) / (k−1)!`
  Verified in this blueprint's own extraction against the book's worked example: `N=6, k=2` gives `C(6,4)=15` splits and `φ[6,2]=5` paths, matching AFML's Figures 12.1–12.2 exactly. **This exact formula — not a min/max test-start approximation — is what Quantara's shared CPCV helper must implement**, per the previously-flagged P0/P1 finding, now made precise: `k=1` reduces CPCV to plain CV (`φ=1`); `k=2` gives `φ[N,2]=N−1` paths while training on `θ=1−2/N` of the data, and the practical rule of thumb is to set `N=φ+1` groups to hit a target path count.
  - **Full algorithm** (AFML §12.4.2, p.165): (1) partition without shuffling into `N` groups; (2) enumerate all `C(N,N−k)` train/test splits; (3) apply the general `getTrainTimes` purge+embargo (§4.5) to every training/testing label pair for every split; (4) fit and forecast on all `C(N,N−k)` splits; (5) assemble the `φ[N,k]` backtest paths and compute **one Sharpe ratio per path**, i.e. CPCV's output is a *distribution* of Sharpe ratios, not a point estimate.
  - **Why this reduces false discoveries** (AFML §12.5, p.166–167, exact formula): the variance of the CPCV sample-mean Sharpe ratio across paths is `σ²[μ_i] = φ⁻¹σ_i²(1+(φ−1)ρ̄_i)`, strictly less than the single-path variance `σ_i²` whenever the average cross-path correlation `ρ̄_i<1` — i.e., CPCV is provably lower-variance (hence lower false-discovery risk) than either walk-forward or plain CV, and the improvement is quantifiable, not merely asserted.
- **Backtesting on synthetic data** (AFML Ch.13, book p.169–193): derives the optimal trading rule (profit-taking/stop-loss pair) *analytically* from an assumed Ornstein-Uhlenbeck price process, with **no historical simulation involved in calibrating the rule at all** — the five-step algorithm (AFML p.173–174) estimates `{σ,φ}` from data, meshes candidate `(π,π̄)` pairs, generates ~100,000 synthetic O-U paths per node, and picks the Sharpe-maximizing node. This is explicitly the recommended alternative to backtest-calibrating exit thresholds, and Quantara's V3 exit-threshold research should be benchmarked against it rather than continuing to select purely from realized-economics grid scans.
- **Deflated Sharpe Ratio / False Strategy theorem** (AFML §14.7.2–14.7.3, p.203–205; MLAM §8.5–8.7, p.111–120, proof in Appendix B p.128–129) — **exact formulas, previously only named, now fully specified:**
  - PSR: `P̂SR[SR*] = Z[(ŜR−SR*)·√(T−1) / √(1−γ̂₃ŜR+((γ̂₄−1)/4)ŜR²)]`.
  - False Strategy theorem (the formal basis for DSR's null): for `K` independent trials with `ŜR_k ~ N[0, V[{ŜR_k}]]` (a *true* Sharpe ratio of zero — a "false strategy"), `E[max_k{ŜR_k}]·(V[{ŜR_k}])^{-1/2} ≈ (1−γ)·Z⁻¹[1−1/K] + γ·Z⁻¹[1−1/(Ke)]`, where `γ≈0.5772` is the Euler-Mascheroni constant. MLAM's own Monte Carlo validates this closely tracks the true empirical maximum across `K` from 2 to 1,000,000 (MLAM p.115–116); at `K=1,000` trials, the expected maximum Sharpe ratio of a *literally worthless* strategy is already **≈3.26**.
  - DSR: identical to PSR but with `SR*` replaced by the False Strategy theorem's `E[max_k{ŜR_k}]` — i.e., DSR asks whether the observed best Sharpe ratio clears the bar a *worthless* strategy would be expected to clear given how many trials were actually run, not whether it clears zero.
  - Estimating the two required inputs — the effective (not nominal) number of independent trials `K`, and the cross-trial variance `V[{ŜR_k}]` — is itself an ML clustering problem, solved in MLAM via **ONC** (§4.9 below) applied to the correlation matrix of trial return series, reducing correlated trial variants to cluster-level "meta-strategies" before computing `K` and `V`. MLAM's own real-data example clusters 6,385 backtested return series down to just **4 differentiated clusters** via ONC (MLAM p.117), used as a *conservative* (lower-bound) trial count.
  - **FWER/Šidák alternative** (MLAM §8.8, p.120–124): `α = 1−(1−α_K)^{1/K}` for a target familywise error rate `α_K`, with the same ONC-derived `K`. MLAM's own worked numeric example is a useful sanity-check fixture: a strategy with nominal single-trial `α≈0.0062` becomes `α_K≈0.0608` — an order of magnitude looser — once corrected for `K=10` ONC-estimated effective trials (MLAM p.122).
- **Determination:** none of PSR, DSR, FWER/Šidák, or PBO/CSCV exist today as a first-class V3 promotion gate (confirmed still-open per the prior deviation register). **This is the concrete deliverable for P0.4/Phase 8 below** — the exact formulas above are what must be implemented, not a generic "add overfitting controls" instruction.

### 4.8 Feature importance (AFML Ch.8, book p.113–128; MLAM Ch.6, book p.74–91)

- **MDI/MDA/SFI** (AFML §8.3–8.4, p.114–120): confirmed as standard reference methods; AFML's own synthetic-data experiment (40 features: 10 informative, 10 redundant, 20 noise) shows both MDI and MDA are **measurably degraded, not catastrophically broken**, by substitution effects among correlated/redundant features (AFML p.122–127) — the book's own remedy in that chapter is PCA-orthogonalization prior to importance analysis (AFML §8.4.2, p.118–120), plus SFI as a substitution-free cross-check. **AFML Ch.8 itself does not describe or endorse anything called "clustered MDA."**
- **Clustered Feature Importance (CFI) is MLAM's contribution** (MLAM §6.5.2, p.85–87), and it is the later, preferred refinement per this blueprint's governance rule (§2): cluster mutually-codependent features first (via ONC, using either correlation-distance or, preferably, variation-of-information distance — the latter explicitly recommended because it also catches *nonlinear* substitution effects that correlation-distance clustering misses, MLAM p.85), then run MDI/MDA **at the cluster level** (summing per-feature MDI within a cluster; jointly shuffling all of a cluster's features together for MDA) rather than per individual feature. MLAM's own experiment on the same 40-feature synthetic dataset shows clustered MDI/MDA correctly separates all 5 non-noise clusters from the 1 pure-noise cluster with far cleaner separation than unclustered MDI/MDA achieved (MLAM p.87–89, Figures 6.5–6.6).
- **Determination:** Quantara's existing "clustered MDA" should be checked against MLAM §6.5.2's exact two-step CFI algorithm (cluster via ONC on a correlation- or VI-distance matrix, **then** aggregate MDI/MDA by cluster) rather than against AFML Ch.8 alone, since AFML Ch.8 does not contain a clustering step at all. If Quantara's current implementation clusters via a fixed Ward-linkage distance threshold on raw correlation rather than ONC, that is the same P1 gap already identified in §4.9/§4.11 below, appearing here in its feature-importance-specific form.

### 4.9 Denoising, detoning, distance metrics, optimal clustering (MLAM Ch.2–4, book p.24–64) — **P1, highest-leverage cheap fix**

- **Marcenko-Pastur denoising** (MLAM §2.2–2.5, p.24–31): for a `T×N` matrix of IID random data with `q=T/N`, eigenvalues of the empirical correlation matrix converge to a known density supported on `[λ₋,λ₊] = σ²(1∓√(1/q))²`; eigenvalues above `λ₊` are the only ones consistent with genuine (nonrandom) signal. The **constant residual eigenvalue method** (MLAM p.29, the book's own preferred/canonical method, preferred over Ledoit-Wolf shrinkage) replaces every eigenvalue below the fitted `λ₊` cutoff with their common average, preserving the correlation matrix's trace, then rescales the diagonal back to 1s. MLAM's own Monte Carlo (MLAM p.32–36) shows this is not a marginal fix: denoising alone cuts minimum-variance portfolio weight RMSE by 59.85% and max-Sharpe weight RMSE by 94.44%, with Ledoit-Wolf shrinkage adding essentially nothing further once denoising has been applied.
- **Detoning** (MLAM §2.6, p.30–32): for clustering specifically, additionally remove the dominant "market" eigenvector (loading ≈`N^{-1/2}` on every item) from the denoised matrix before clustering, since a strong common component masks subtler subgroup structure. The detoned matrix is singular by construction and must **not** be used directly for mean-variance optimization — map optimal weights back via `ω*=W₊f*` using only the surviving eigenvectors.
- **Variation of Information (VI) as a true distance metric** (MLAM §3.7–3.8, p.42–43): unlike correlation (which fails the triangle inequality and can only capture linear codependence), `VI[X,Y]=H[X]+H[Y]−2·I[X,Y]` **is** a proper metric, and its normalized/bounded form (Kraskov's `V̆I[X,Y]=1−I[X,Y]/max{H[X],H[Y]}`) is recommended over the plain-normalized alternative because it is provably tighter. MLAM's own experiment shows correlation **fails outright** on a symmetric nonlinear relationship (`y=100|x|+ε` gives correlation ≈ −0.008, i.e., appears to detect *no* relationship at all) while normalized mutual information correctly detects it (≈0.64) (MLAM p.49–50).
- **ONC (Optimal Number of Clusters)** (MLAM §4.4, p.54–59) — full two-stage algorithm: base clustering runs k-means across a double loop over random initializations × candidate `k`, scoring each attempt by the silhouette-based quality metric `q = E[{S_i}]/√V[{S_i}]` (a t-stat-like measure of mean cluster quality relative to its own dispersion, not just mean quality) and keeping the single best-scoring `(init,k)` combination; a second, higher-level stage identifies clusters with below-average quality, **recursively re-clusters just that subset**, and accepts the improved composite clustering only if its quality genuinely improves over the base result, else falls back to the base clustering unchanged. MLAM's own Monte Carlo validation (block-diagonal correlation matrices with known injected cluster structure) shows ONC recovers the correct cluster count with median ratio ≈1.0 across a wide range of true cluster counts (MLAM p.62–63).
- **Determination — this is a P1 item, but it is the single highest-value-per-effort item in this entire blueprint.** Both the feature-clustering layer (§4.8) and the portfolio-clustering layer (§4.10/§4.11) currently use raw undenoised correlation with a fixed Ward-linkage distance threshold instead of ONC. Replacing this in one place (a shared `denoise_correlation()` + `onc_cluster()` utility) fixes the same identified gap in two downstream consumers at once, and MLAM's own numbers above suggest it is likely to produce a larger, more immediately measurable improvement than any other single item in this document.

### 4.10 Portfolio construction — HRP and NCO (AFML Ch.16, book p.221–245; MLAM Ch.7, book p.92–104)

- **HRP algorithm, exact and complete** (AFML §16.4, p.223–231): three stages — (1) **tree clustering**: correlation-distance `d_{i,j}=√(½(1−ρ_{i,j}))` (a proper metric, proof in AFML Appendix 16.A.1), a second "distance of distances" `d̃_{i,j}=√(Σ_n(d_{n,i}−d_{n,j})²)` computed over the columns of the distance matrix itself, then single-linkage agglomerative clustering on `d̃`; (2) **quasi-diagonalization**: reorder the covariance matrix by recursively expanding the linkage tree's final merge so similar assets sit adjacent, without any change of basis; (3) **recursive bisection**: starting from unit weights, recursively bisect the quasi-diagonalized order into contiguous halves, weight each half's variance by *diagonal-only* inverse-variance allocation (`w̃=diag[V]⁻¹/tr(diag[V]⁻¹)`, deliberately **not** the full covariance inverse — this is exactly what makes HRP robust to singular/ill-conditioned covariance matrices), split the parent weight between the two halves in inverse proportion to their variances (`α=1−Ṽ⁽¹⁾/(Ṽ⁽¹⁾+Ṽ⁽²⁾)`), and recurse. AFML's own out-of-sample Monte Carlo shows HRP achieves **72.47% lower variance than CLA (Markowitz)** and **38.24% lower than plain inverse-variance/risk-parity**, despite CLA's stated objective literally being minimum variance (AFML p.234–236) — the mechanism is that CLA's concentration is destabilized by idiosyncratic shocks while naive IVP is destabilized by ignoring correlation structure altogether, and HRP alone hedges both failure modes.
- **One implementation subtlety flagged for direct verification against Quantara's code:** AFML's own reference implementation passes the raw correlation-distance matrix directly to `scipy.cluster.hierarchy.linkage(dist,'single')` rather than materializing a separate distance-of-distances step first — worth confirming Quantara's HRP implementation reproduces the same effective semantics scipy's single-linkage call collapses into, not just the narrative three-step description.
- **NCO (Nested Clustered Optimization), full algorithm** (MLAM §7.6, p.96–100): a "wrapper" method, not a replacement allocation rule — it is agnostic to which underlying optimizer (minimum-variance, max-Sharpe, CLA, Black-Litterman) is used within it. Three steps: (1) optionally denoise (and, per an explicit book exercise, optionally detone) the covariance matrix, then cluster it via ONC with `maxNumClusters = N/2` (singleton clusters cannot raise the condition number, so only clusters of size ≥2 need be considered); (2) compute the **intracluster** optimal allocation independently within each cluster using only that cluster's sub-covariance, then form a reduced `K×K` cluster-level covariance matrix from those intracluster weights; (3) compute the **intercluster** optimal allocation on the reduced (by construction close-to-diagonal, hence numerically well-behaved) cluster-level covariance matrix, and multiply intracluster × intercluster weight for each security's final allocation. MLAM's own Monte Carlo (50 securities, 10 blocks) shows NCO cuts minimum-variance RMSE by **47.02%** and max-Sharpe RMSE by **54.83%** versus raw Markowitz, with Ledoit-Wolf shrinkage again adding nothing on top of NCO (MLAM p.100–101).
- **The mechanism connecting these two chapters** (MLAM §7.4–7.5, p.94–96): Markowitz's instability has **two independent causes** — noise (regulated by `T/N`, the Marcenko-Pastur domain) and **signal itself** (regulated by intracluster correlation strength, *independent of* `T/N` and *not* fixable merely by gathering more observations). A worked example shows a 500×500 matrix with two 250-asset blocks at intrablock correlation 0.5 has condition number 251, and — critically — reducing correlation in only *one* of the two blocks does **not** reduce the overall condition number, because the instability is dominated by whichever cluster is most correlated, and it corrupts the *entire* matrix (MLAM p.95–96). This is precisely why containing instability *per cluster* (NCO's core idea) works where global shrinkage does not.
- **Determination:** AFML's HRP should be preserved as the baseline (per the prior deviation register's "Preserve as baseline" status) — the exact algorithm above is what to verify Quantara's implementation against line by line. **NCO does not currently exist in Quantara and should be added as a benchmark allocator**, compared against HRP under controlled out-of-sample Monte Carlo and perturbation tests, per MLAM's own explicit guidance not to replace HRP simply because NCO is newer (MLAM §7.8, p.102: "use the Monte Carlo approach... to determine, for a particular set of input variables, which optimization method... is most robust for that specific case — rather than dogmatically always using one method"). NCO's covariance input should be the denoised (and optionally detoned) matrix from §4.9, not a raw empirical one — MLAM is explicit that denoising should generally precede NCO's clustering step, especially "for large matrices, where T/N is relatively low" (MLAM p.98).

### 4.11 Structural breaks, entropy, microstructure (AFML Ch.17–19, book p.249–300)

- **CUSUM/SADF structural-break tests** (AFML §17.3–17.4, p.250–260): the Supremum Augmented Dickey-Fuller test (`SADF_t = sup_{t0∈[1,t−τ]}{ADF_{t0,t}}`, backwards-expanding-window t-statistic of the ADF regression coefficient, computed at every `t`) is the canonical, recommended method for detecting explosive/bubble regimes without assuming a known single break date, superseding the simpler Chow-type Dickey-Fuller test which assumes exactly one break and no reversion. Quantara's existing CUSUM/HMM/regime infrastructure should be checked against this specific formula if it claims to implement AFML-style structural-break detection; if it is HMM-based regime detection instead, that should remain registered as a separate, non-AFML regime-detection method (which is a perfectly legitimate design choice, just not the same object as SADF).
- **Entropy features** (AFML Ch.18, p.263–279): Shannon entropy, the plug-in estimator, and the Kontoyiannis Lempel-Ziv-based entropy-rate estimator (`H̃_n=(1/n)Σ log₂[i]/L_i^i`, using match lengths against a symmetric backward/forward window) are the canonical toolkit; AFML explicitly recommends encoding **fractionally-differentiated** series (not integer-differenced) before discretizing for entropy estimation, to retain memory (AFML p.269). This connects directly to VPIN/PIN (§4.11 below) via order-flow-imbalance persistence.
- **Microstructure features — this is the single most important data-availability finding in this document, verified feature-by-feature (AFML §19.3–19.6, p.281–298):**

  | Feature | Book reference | Requires true trade prints (price+volume+aggressor side)? |
  |---|---|---|
  | Tick rule | AFML §19.3.1, p.282 | **Yes** — needs an executed-trade price sequence to sign |
  | Roll model (effective spread from serial covariance) | AFML §19.3.2, p.282–283 | **Yes** — applying it to mid-quotes estimates zero spread by construction, defeating its purpose |
  | Parkinson high-low volatility estimator | AFML §19.3.3, p.283–284 | **No** — only needs High/Low per bar |
  | Corwin-Schultz spread estimator | AFML §19.3.4, p.284–286 | **No** — only needs High/Low per bar; explicitly designed for markets with no order book at all (e.g. corporate-bond BWIC) |
  | Kyle's lambda | AFML §19.4.1, p.286–288 | **Yes** — needs signed volume (aggressor side × traded size) |
  | Amihud's lambda | AFML §19.4.2, p.288–289 | **Yes** — needs traded dollar volume |
  | Hasbrouck's lambda | AFML §19.4.3, p.289 | **Yes** — full trade-and-quote (TAQ) data |
  | PIN / VPIN | AFML §19.5.1–19.5.2, p.290–292 | **Yes** — needs buy/sell-classified trade volume |
  | Order-size distribution, cancellation rates, TWAP detection, serial correlation of signed flow | AFML §19.6, p.293–296 | **Yes**, and cancellation-rate features additionally need order-book/FIX message data beyond even trade prints |

  **Bottom line: given Quantara's raw data is Bid/Ask quote ticks (not confirmed trade prints) for most instruments, only the Parkinson and Corwin-Schultz estimators are directly implementable as AFML specifies.** Any existing or future "PIN," "VPIN," or "Kyle's lambda"-named feature in Quantara that is actually built from a quote-midpoint-change proxy rather than genuine signed trade prints must be labeled a `DATA_CONSTRAINED_ADAPTATION`, not a faithful reproduction — this is a direct, mechanical determination from the book's own stated data requirements, not a judgment call. (BTCUSD may be a partial exception if Quantara's crypto feed includes genuine trade prints with side — worth checking per-asset, since this table's applicability is data-source-dependent, not universal across Quantara's instrument list.)

### 4.12 Bet sizing (AFML Ch.10, book p.141–149) — **P0/P1, formulas independently double-verified**

Reproduced here in full because it is the canonical reference Quantara's live sizing must be benchmarked against, and both this blueprint's own extraction process and the book's own printed Python snippet (Snippet 10.1, `getSignal`) were checked against each other and agree exactly, leaving no ambiguity:

- **Binary case:** null `p₀=1/2`; `z = (p[x=1]−1/2) / √(p[x=1]·(1−p[x=1]))`; **bet size `m = 2·Z[z]−1`**, `m∈[−1,1]`.
- **One-vs-rest (multi-class) case:** let `p̃=max_i{p_i}` be the predicted label's probability, null `p₀=1/‖X‖`; `z=(p̃−1/‖X‖)/√(p̃(1−p̃))`; **bet size `m = x·(2·Z[z]−1)`**, where `x` is the predicted label supplying the sign.
- **Averaging active bets** (AFML p.144): average the sizes of all bets concurrently active at a given time (defined via the same `t1`-based overlap logic as Ch.4's concurrency), to avoid excessive turnover from naively overriding an old bet with each new signal.
- **Size discretization** (AFML p.144–145): `m* = round(m/d)·d` for a step size `d∈(0,1]`, to avoid overtrading on marginal signal changes.
- **Dynamic bet sizing and limit prices** (AFML §10.6, p.145–147): a sigmoid target-position function `q̂ = Int[m[ω,f−p_t]·Q]`, `m[ω,x]=x/√(ω+x²)`, with a closed-form breakeven limit price `p̃` derived from the inverse function `L[f,ω,m]=f−m·√(ω/(1−m²))`, and a calibration formula `ω=x²·(m*⁻²−1)` for choosing `ω` from a desired (divergence, size) pair. **A power-function alternative sizing curve is explicitly presented (`m̃=sgn[x]·|x|^ω`) but the book does not derive a closed-form limit price for it** — this is explicitly left as an unsolved reader exercise (AFML p.147, Exercises 10.6–10.7), so any Quantara implementation using a power-function-shaped sizing curve cannot claim a canonical AFML limit-price formula for it; that derivation would be original work, not extraction.
- **Determination:** the AFML Ch.10 reference module Task 1 installed should implement exactly the two formulas above (binary and one-vs-rest), no more and no less. Quantara's live empirical-break-even-rescaled sizing remains a legitimate `QUANTARA_EXTENSION`, but per §1 item 2 it must be benchmarked against this exact reference out of sample before being trusted as the production default, and the benchmark comparison should be an explicit, recorded promotion gate (Phase 7 below), not an assumption.

Research hierarchy: inner purged CV/CPCV for feature selection and hyperparameters; outer CPCV (using the exact `φ[N,k]` path-count formula, §4.7) or a locked OOS holdout for honest evaluation; a final untouched chronological embargo, used once, after all research choices are frozen. **Gate:** every reported OOS metric declares whether and how that data influenced any upstream choice.

### Phase 6 — Feature importance becomes theory discovery

Upgrade clustered feature importance to MLAM's actual CFI algorithm (§4.8/§4.9): denoise the correlation matrix (Marcenko-Pastur, constant-residual-eigenvalue method), detone only when a statistically meaningful common component is present, cluster via ONC (not a fixed Ward-linkage threshold) on either correlation-distance or variation-of-information distance, then aggregate MDI/MDA at the cluster level. After feature importance, require an edge theory dossier per the prior blueprint's specification (mechanism, funding agent/constraint, expected regimes, counterfactual, falsification test, capacity/decay expectations) before model promotion. **Gate:** no edge is called a discovery merely because its backtest is positive.

### Phase 7 — Model, probability, calibration, and size

Train the secondary model on the same target the probability will mean in production (P0.2). Produce OOF probabilities via the frozen inner CV process (Phase 5). Calibrate against the same label, no in-fold reuse. Maintain both `afml_ch10_bet_size_reference` (§4.12's exact formulas) and `quantara_extension_bet_size` as parallel, independently tested outputs; promotion requires the extension to demonstrate out-of-sample value over the reference after trial-count correction (Phase 8). **Gate:** probability semantics can be written in one sentence — e.g., "0.67 means an estimated 67% probability that this pre-defined side-specialized opportunity finishes with positive net-executable R under execution contract X."

### Phase 8 — Backtest-overfitting firewall — **the exact formulas are now fully specified in §4.7, this was previously the vaguest phase and is now the most concrete**

Add: PSR and DSR (exact formulas, §4.7); the False Strategy theorem's `E[max_k{ŜR_k}]` as DSR's actual null, estimated via ONC-derived effective trial count `K` and cross-trial variance `V[{ŜR_k}]` (MLAM §8.7); FWER/Šidák correction as an alternative/complementary lens (`α=1−(1−α_K)^{1/K}`); CPCV's exact backtest-path distribution (§4.7); PBO via the CSCV algorithm (AFML §11.6, p.155–158, its own exact combinatorial procedure); synthetic-data tests via either AFML Ch.13's O-U-process framework (for trading-rule/exit-threshold questions) or MLAM Appendix A's broader resampling/Monte-Carlo taxonomy (for strategy-discovery questions); return concentration (HHI-based, AFML §14.5.1) and time-under-water (AFML §14.5.2); implementation shortfall (AFML §14.6). **Gate:** promotion report includes false-discovery/selection-risk evidence (DSR and/or FWER-corrected significance), not only mean R, profit factor, F1, or drawdown.

### Phase 9 — Portfolio construction upgrade

Retain HRP as the AFML baseline (verify against §4.10's exact three-stage algorithm). Add the covariance treatment layer from §4.9 (empirical → denoised → optionally detoned, with condition-number diagnostics) before any clustering/allocation step. Add NCO (§4.10's exact algorithm) as a benchmark allocator, not a default replacement — compare HRP, NCO, and any existing Quantara allocator under controlled OOS Monte Carlo and covariance-perturbation tests, exactly as MLAM's own conclusion recommends (§4.10). Only after statistical allocation is determined should broker min-lot, lot-step, currency conversion, and prop-firm constraints be applied. **Gate:** portfolio allocation is robust to reasonable covariance perturbations and is not an artifact of one noisy empirical correlation matrix.

### Phase 10 — Execution and implementation shortfall

Preserve exact quote-side Bid/Ask replay (confirmed a genuine Quantara strength, not a book requirement it needs to match — AFML does not prescribe Quantara's specific execution-realism layer, but nothing in it conflicts with the books either). Expand cost attribution using AFML §14.6's implementation-shortfall categories (broker fees per turnover, average slippage per turnover, dollar performance per turnover, return on execution costs) so every trade decomposes into gross edge, spread cost, entry delay/staleness, modeled slippage, commission, financing/swap where relevant, min-lot/rounding distortion, and missed-opportunity cost. Do not model a cost for which there is no defensible data; mark it unknown instead. **Gate:** simulated net-executable economics reconcile to actual live implementation shortfall within a monitored tolerance once paper/live observations accumulate.

### Phase 11 — Portfolio oversight lifecycle

Implement AFML's own stated strategy lifecycle explicitly (AFML §1.2.2, p.4–5): `RESEARCH → EMBARGO (test on post-backtest data) → PAPER (live feed, no capital) → GRADUATION (small real capital) → REALLOCATION (concave function of confirmed performance) → DECOMMISSION (when theory is no longer backed by evidence)`. For each transition, define minimum evidence, expected-vs-realized divergence limits, and authorization authority. **Gate:** a research backtest can never jump directly to full live capital.

### Phase 12 — Rebuild the V3 edge universe

Once Phases 0–11's foundations are coded and tested: (1) freeze the new semantic contracts; (2) confirm the 120-second live signal-age policy is applied everywhere (already corrected by Task 1, verify no stale artifacts remain); (3) invalidate every artifact whose target, event geometry, execution contract, CV split, sample weight, FFD, feature set, or probability semantics changed, per the dependency table in §7; (4) re-run each edge from the earliest invalidated station; (5) re-run feature importance/theory dossiers where the target changed; (6) re-run model tuning and OOF generation; (7) re-run same-target calibration and AFML reference sizing; (8) run the Phase 8 overfitting/false-discovery gates; (9) export new edge manifests only after all gates pass; (10) re-run independence analysis; (11) rebuild portfolio allocator outputs using the treated (denoised, ONC-clustered, NCO-benchmarked) covariance pipeline; (12) run broker/prop stress and Monte Carlo; (13) rebuild live manifest; (14) re-certify Phase C/D against the newly selected V3 universe; (15) paper-trade before graduation. **Gate:** old August-generation deployment artifacts are archived as prior-generation evidence and cannot satisfy current V3 certification by filename alone.
